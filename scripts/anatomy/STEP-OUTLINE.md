# Автоматический контур из STEP

## Одна команда

Все пути к данным — абсолютные; Python запускается с `-I`. Рабочий каталог —
проект, **не** папка с моделями. Зависимости уже есть в
`/home/foxqa/.cache/stroygaz-step-venv`: cadquery-ocp, numpy, Pillow и VTK.
Для EGL нужен Mesa EGL либо драйвер GPU. X11/GUI не используются.

```bash
/home/foxqa/.cache/stroygaz-step-venv/bin/python -I \
  /home/foxqa/Projects/stroygaz/scripts/anatomy/step-outline.py \
  '/absolute/model.step' --output-dir /absolute/output --contact-sheet

# Выбрать номер по contact-sheet.json; отражение выполняется ДО поворота.
/home/foxqa/.cache/stroygaz-step-venv/bin/python -I \
  /home/foxqa/Projects/stroygaz/scripts/anatomy/step-outline.py \
  '/absolute/model.step' --output-dir /absolute/output --rotation 350 --mirror x
```

Дозирование: **`--rotation 350 --mirror x`** в исходных осях STEP. Для новых
моделей нет встроенной таблицы ориентаций и никаких исключений геометрии.
Contact sheet: 1–8 без зеркала, 9–16 с зеркалом X; в каждой группе 0–315°,
шаг 45°. Это отдельный быстрый проход по грубой сетке с закрашенным силуэтом.

Результат: `outline.svg`, `outline.png`, `report.json`; диагностика:
`normals.png`, `depth.png`, `silhouette.png`, `normal-edges.png`,
`depth-edges.png`, `cad-edges.png`, `skeleton.png`, `vector-coverage.png`.

## Почему не HLR

В `output/anatomy/dosing-hlr/diag/FINDINGS.md` уже локализованы независимые
ошибки прежнего подхода:

1. Poly HLR классифицирует часть видимых силуэтов стойки/перекладины как скрытые.
   Уточнение сетки не устраняет этот дефект.
2. Фильтр размера тела удаляет функциональные тройники, отводы, редукции и
   короткие трубы вместе с мелочью. Понижение порога не является гарантией.
3. Исключение тела удаляет поверхность целиком; ручные сдвиги дополнительно
   нарушают взаимное положение труб и баков.

Новый конвейер читает XCAF, накапливает положения всех вхождений сборки и
передаёт **все поверхности** в общий ортографический z-buffer.
На каждом отсчёте побеждает ближайший треугольник, независимо от имени,
размера и порядка тел. Нормали гладкие внутри CAD-грани, разрывные на изломах:
триангуляционная диагональ не становится штрихом.

Силуэты выделяются по маске покрытия; внутренние контуры — по разрывам
глубины и нормалей. Глубина проверяется относительно касательных плоскостей,
поэтому наклонная плоскость не превращается в полосу ложных контуров.
**Одних этих разрывов недостаточно:** копланарная рамка дисплея не меняет
глубину/нормаль, а плавная канавка бака не обязана иметь острый излом. Поэтому
исходные CAD-кромки тоже растрируются с проверкой видимости по **тому же**
z-buffer. Исключаются только параметрические швы периодических поверхностей
и вырожденные рёбра нулевой длины, не тела. Кривые не проходят через ошибочную
классификацию HLR. Так сохраняются и рамки дисплеев, и геометрические канавки.
Замыкание зазоров — один пиксель высокого разрешения; оно **не удаляет**
исходные пиксели. Утончение и трассировка не отбрасывают короткие цепочки,
компоненты, точки и замкнутые циклы. У RDP ограничена геометрическая ошибка.
Potrace не нужен: его заполненные обводки дали бы переменную толщину вместо
штриха сайта 1,05 px. SVG выбирает короткие относительные/абсолютные команды
после округления координат до 0,01 px; относительные дельты не накапливают
ошибку. Это экономит место без удаления цепочек или дополнительного RDP.

### Граница гарантии

Гарантируется отсутствие **программного удаления тел**, произвольных сдвигов
и молчаливого пропуска непостроенной грани. Перед экспортом проверяется
тесселяция каждой грани. При сбое — повторная мелкая тесселяция. Если она не
помогла, **исходная грань** передаётся в точное пересечение с лучами пикселей
и дополняет тот же z-buffer. Это не HLR и не рисование рёбер поверх поверхности:
каждое попадание участвует в той же проверке глубины. Проверяются только пиксели
консервативного bbox грани, уже перекрытые более близкой геометрией пропускаются.
Ни поверхность, ни контуры обрезки STEP не заменяются и не исправляются вручную.
Исходные проблемные грани сохраняются в `meshing-diagnostics/`; для каждой в JSON
есть `valid_brep`, число проверенных лучей, попаданий и записей в z-buffer.
Ошибка пересечения останавливает проход, а не выдаёт частичную схему.
Нулевые по машинной точности площади фиксируются отдельно: это не поверхности,
которые можно растрировать. Кеш числовой, без pickle, с проверкой SHA-256 STEP.

Это **не** обещание видимости скрытых объектов или сохранения любой субпиксельной
резьбы. Невалидная топология исходного STEP также отмечается в JSON: её нельзя
выдавать за математически корректную модель. В конечном разрешении соседние
линии могут слиться. Только геометрические кромки и кривые из STEP могут
сохраниться: негеометрические надписи/текстуры из PNG в STEP отсутствуют. В отличие от
удаления тела, повышение разрешения здесь возвращает геометрическую мелочь
без изменения состава сборки.

## Детализация и размер SVG

| Параметр | По умолчанию | Что меняет |
|---|---:|---|
| `--supersample` | 4 | 3040×2000; 8 даёт 6080×4000 и более тонкие детали |
| `--mesh-error` | 0.18 | Оценка погрешности хорды в px; меньше — точнее силуэт, больше сетка |
| `--angular-deflection` | 0.2 | Допуск тесселяции в радианах |
| `--crease-angle` | 32 | Угол разрыва нормалей; меньше — больше слабых складок |
| `--depth-jump` | 0.35 | Разрыв относительно касательных плоскостей, в px холста |
| `--edge-depth-tolerance` | 0.45 | Допуск видимости CAD-кромки по глубине в px, не меньше ошибки хорды сетки |
| `--simplify` | 0.18 | Начальная погрешность RDP, px |
| `--max-simplify` | 0.5 | Предельная погрешность при подгонке SVG к 300 КиБ; меньше половины штриха |

Геометрическая погрешность сетки в мм и фактическая оценка в px сохраняются
в отчёте. Увеличение supersample не требует повторного чтения STEP: годится
та же числовая сетка. Contact sheet имеет отдельный грубый кеш; если доступен
только готовый финальный кеш, он используется без нового чтения STEP, с
низким разрешением силуэта. При первом запуске строится грубая сетка.

SVG фиксирован: 760×500, камера 55°/31°, вписывание всей геометрии с pad=20,
`#383e43`, 1,05 px, круглые стыки и концы. Если достичь бюджета без превышения
допустимой погрешности не удалось, программа явно пишет предупреждение;
она не удаляет детали ради размера файла. Проверяйте `status`, `within_budget`
и `raw_edge_coverage` в JSON. Последняя метрика проверяет перевод найденных
растровых контуров в линии, а не полноту исходного STEP.

## Пакетная обработка

```bash
/home/foxqa/.cache/stroygaz-step-venv/bin/python -I \
  /home/foxqa/Projects/stroygaz/scripts/anatomy/step-outline-all.py \
  '/absolute/input/folder' --output-root /absolute/output/anatomy \
  --orientations /absolute/choices.json --timeout 1200
```

`choices.json` принимает **только** `rotation` и `mirror`, ключ — slug папки:

```json
{"ustanovka-prigotovleniya-i-dozirovaniya":{"rotation":350,"mirror":"x"}}
```

Неуказанные ориентации — `0 / none`, то есть предварительные, а не выбранные
заказчиком. `--contact-sheet` у batch делает только листы выбора. STEP
обрабатываются последовательно, каждый отдельным Python-процессом; сбой одного
не пропускает остальные. В папках — `command.txt` и `run.log`, в корне —
`batch-report.json` (wall-time, RSS через Linux wait4, код выхода каждого).
Таймаут уничтожает только отдельную группу дочернего процесса этой модели.

## Приёмка и тесты

`--reference /absolute/reference.png` создаёт `outline-review.png`. Если ракурс
референса другой, используйте также `--comparison-svg /absolute/exact.svg`
и `--comparison-report /absolute/dosing-hlr-report.json`. Программа проверит,
что это exact HLR **того же STEP, с нулевым порогом, без исключений, сдвигов и
подавления крепежа**, в той же ориентации; fit приводится аналитически по
scale/origin. Никакого ручного совмещения отдельных деталей. Exact HLR нужен
только как контрольное наложение, не входит в производственный конвейер.

```bash
/home/foxqa/.cache/stroygaz-step-venv/bin/python -I \
  /home/foxqa/Projects/stroygaz/scripts/anatomy/step-outline.test.py
```

Тесты чистых функций не импортируют OCC/VTK: камера, порядок преобразований,
вписывание, глубина/складки, сохранение маленьких компонентов, утончение,
петли/развилки/точки, RDP, стиль SVG, валидация контрольного exact, slug,
ограничение настроек модели ориентацией, таймаут и RSS пакетного запуска.
